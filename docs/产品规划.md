## 一、产品定位与差异化底牌

对标对象是 Postman / Apifox 的**付费版**能力，但**不逐条抄功能表**——只做
「测试团队日常最痛 × 现有架构顺手 × 简历/演示有亮点」交集里的功能。

三张底牌在做任何取舍时都不能丢：

| 底牌 | 为什么商业化平台给不了 |
|:---|:---|
| **自托管 + CI-first** | 令牌触发、`exit_code_for_ci` 直接判流水线成败；引擎直连公司内网服务——Postman 的监控跑在它家云上，内网 API 够不着 |
| **引擎级真实性** | 断言明细平台重建（rebuilt 标注）、「该跑没跑」对账强制 error、归因三态——Postman 的测试是 JS 脚本断言，没有假绿防护概念 |
| **原创分析层** | 性能回归（F11）/ 资产健康度（F12）/ 失败聚类（F13）——两家付费版都没有同级物 |

**产品哲学**：结构化优先，不用「任意 JS 自由脚本」当逃生舱；结构化覆盖 80% 场景，
剩下 20% 用函数库（R6）解决。自由度会稀释「可校验、可归因」的核心差异化。

## 二、对标矩阵（付费版能力 vs 本平台现状）

| 能力 | Postman/Apifox 付费版 | 本平台现状 | 差距 | 立项 |
|:---|:---|:---|:---|:---|
| DB 步骤（前置造数 / 后置校验落库） | Apifox 招牌，团队刚需第一 | 无（步骤仅 HTTP/WS/GraphQL） | ⭐⭐⭐ | **R1** |
| 智能 Mock（字段级动态数据） | Apifox 卖点 | F4/F5 整段 response_body 回放 | ⭐⭐⭐ | **R2** |
| AI 生成用例/断言 | Apifox AI、Postbot | 无 | ⭐⭐ | **R3** |
| 用例评审流（fork/审批/生效） | Postman 收费主打 | F8 变更历史已留痕，无审批态 | ⭐⭐ | **R4** |
| API 治理 lint（命名/描述/规范） | Enterprise 卖点 | 静态校验器具备一半能力 | ⭐⭐ | **R5** |
| 自定义函数库（前置/后置脚本的结构化替代） | 两家核心 | 引擎 hooks/debugtalk 存在，UI 未暴露 | ⭐ | **R6** |
| 压测（并发/时长/报告） | Apifox 简单压测 | hrp 引擎自带 boomer 模式，平台未接 | ⭐⭐ | **R7** |
| 敏感变量加密存储 | Enterprise | 仅展示层掩码（F7/F2） | ⭐ | **R8** |
| 企业登录（LDAP/SSO） | Enterprise | 账号密码 + admin/member 两档 | ⭐ | **R9** |
| 云端监控 / 多地域调度 | Postman 监控 | 自托管调度器（本就是卖点） | — | ❌ 不做 |
| API 市场 / 插件生态 | 两家均有 | — | — | ❌ 不做 |
| 移动 / UI 自动化 / 浏览器录制 | Apifox 部分支持 | 引擎定位为接口层 | — | ❌ 不做 |
| gRPC | Apifox/Postman 支持 | 已明确不做（需 protobuf 运行时，独立立项） | — | ❌ 不做 |

## 三、路线图

### 第一梯队（P0：补齐付费版高频刚需——做完这三个，测试团队没有理由再开 Apifox）

#### R1 数据库步骤（db 步骤：前置造数 / 后置校验落库） ｜ 待开发 ｜ P0 ⭐⭐⭐

- **目标**：用例步骤新增 `db` 类型，可连接 MySQL / PostgreSQL 执行 SQL，
  前置场景=造数/清理，后置场景=查询落库结果并**当断言用**。
- **对标**：Apifox 数据库操作（付费版核心能力之一）。
- **范围**：本期支持 MySQL 5.7+/8 与 PostgreSQL 14+；连接串存环境级配置（掩码展示）；
  查询结果支持单值/行/行集三种提取；不做 SQL 构建器、不做多数据源事务。
- **验收要点**：
  1. 用例第 1 步插入测试数据，第 2 步调接口，第 3 步查库断言「落库字段与请求一致」；
  2. 连接串错误时步骤报 `error` 并归因 `environment`（不静默）；
  3. SQL 结果提取的变量可供后续 HTTP 步骤引用（与 D6 提取同语义）；
  4. 数据库设计文档新增 `db_source` 表（项目级连接配置，密码掩码）。
- **技术要点**：hrp 引擎不认识 db 步骤——编译为引擎的 hook 函数调用（debugtalk.py
  由平台生成，内置 `db_query/db_exec` 函数），变量提取走引擎既有 extract 语法；
  静态校验器增加 SQL 只读/写分类警告（后置 SELECT 前的 INSERT 不告警，反之告警）。
- **工作量级**：L ｜ **依赖**：无

#### R2 智能 Mock（字段级动态数据） ｜ 待开发 ｜ P0 ⭐⭐⭐

- **目标**：Mock 响应按**字段名模式 + 类型**自动生成动态数据
  （`*name`→随机姓名、`*phone`→手机号、`*id`→自增、`*time`→当前时间戳……），
  命中不了的字段回退 R 系列之前的 F4 整段 response_body。
- **对标**：Apifox 智能 Mock。
- **范围**：内置规则库 ≥30 条（姓名/手机/邮箱/身份证/地址/金额/枚举/自增/时间戳/UUID）；
  项目级 + 全局级两级自定义规则（字段名通配 + 生成器：regex/enum/自增/函数）；
  F5 导入 OpenAPI 时按 schema 字段名**自动建议**规则（预览里勾选启用）。
- **验收要点**：
  1. 无任何配置时，按字段名内置规则生成合理动态值（两次请求值不同）；
  2. 自定义规则优先于内置；显式 response_body 优先于智能生成（用户写死的不会被覆盖）；
  3. Mock 页可实时预览「这份配置下一次请求会返回什么」；
  4. 命中日志标注每个字段的值来源（内置规则/自定义/回退），延续「来源必须标注」原则。
- **技术要点**：`mocksvc` 扩展字段级生成器；`mock_rule` 新表（或全局配置表）；
  F4 的 `X-Mock-Source` 头语义扩展。
- **工作量级**：M ｜ **依赖**：F4/F5（已完成）

#### R3 AI 用例生成（接口定义 → 候选用例 + 断言草稿） ｜ 待开发 ｜ P0 ⭐⭐

- **目标**：选中接口（或整组接口），LLM 产出候选用例草稿（正向/边界/异常三类），
  人工勾选后入库。**AI 只产草稿，永不直接执行。**
- **对标**：Apifox AI、Postbot。
- **范围**：LLM 接口走 OpenAI 兼容协议（平台配置 base_url/key/model，支持本地部署网关）；
  输入=接口定义（含 F5 导入的 schema 与响应示例）；输出经静态校验器过滤后才进预览；
  交互复用 F5 的「预览 → 勾选 → 提交」两段式。
- **验收要点**：
  1. 对一个有 schema 的接口生成 ≥3 条候选用例（正向 + 边界 + 异常），全部通过静态校验；
  2. AI 产出的断言检查表达式符合契约口径（`body.xxx`，编译期归一兜底）；
  3. 未配置 LLM 时功能入口隐藏，不报错；调用失败给可读错误；
  4. 预览项标注「AI 生成」来源，入库后 `source=ai` 可追溯。
- **技术要点**：新增 `aisvc`（单一 provider 协议，不绑厂商）；提示词工程
  （接口定义 → 结构化 JSON 输出，失败重试一次）；与 R5 治理联动（AI 产出也守规范）。
- **工作量级**：M ｜ **依赖**：F1/F5（已完成）

### 第二梯队（P1：协作与治理深化——30 人团队规模化使用后的刚需）

#### R4 用例评审流（变更 → 待评审 → 批准生效） ｜ 待开发 ｜ P1

- **目标**：用例/接口的修改可进入「待评审」态，批准后才对全员生效；未批准的改动
  在变更历史里可见、可对比、可驳回。
- **对标**：Postman 收费版的 fork / PR 流程。
- **范围**：本期只做「修改型变更」的评审（新建与删除直接生效）；管理员可配置
  项目级开关（关 = 维持现状即改即生效）；驳回必填理由并留痕。
- **验收要点**：
  1. 开启评审的项目，member 修改用例后其他人看到的仍是旧版，变更历史显示「待评审」；
  2. 管理员批准后新版本生效，diff 摘要与 F8 同款；
  3. 驳回后旧版继续生效，驳回理由入变更历史；
  4. 评审态的用例可正常执行旧版（评审不阻塞回归）。
- **技术要点**：版本快照表 + 实体状态位；执行取「已生效版本」；与 F8 审计同表族。
- **工作量级**：L ｜ **依赖**：F8（已完成）

#### R5 API 治理规则集（可配置 lint + 治理分） ｜ 待开发 ｜ P1

- **目标**：把静态校验器扩展成**可配置的规范规则集**：接口命名/描述必填/响应 schema
  完整性/断言覆盖要求/超时配置等；产出「治理分」并入 F12 健康度。
- **对标**：Postman Enterprise 的 API Governance（Spectral 规则思路）。
- **范围**：规则平台预置 + 项目级开关；本期不做自定义 DSL（规则集内置枚举即可）。
- **验收要点**：
  1. 停用「描述必填」规则后相关违规不再上报，启用即恢复；
  2. 治理分与健康分并列展示，扣分明细逐条可跳转；
  3. 新增规则不影响既有用例的保存与执行（lint 是旁路，不是门禁）。
- **技术要点**：`validator` 规则化改造（规则注册表 + severity + 项目级开关表）。
- **工作量级**：M ｜ **依赖**：F1/F12（已完成）

#### R6 自定义函数库（debugtalk 可视化管理） ｜ 待开发 ｜ P1

- **目标**：在 UI 管理每项目（或全局）的 debugtalk.py 函数文件：在线编辑、语法校验、
  函数清单展示；断言/变量/请求里以 `${func(...)}` 引用。
- **对标**：Postman 前后置脚本的结构化替代——脚本不散落在用例里，集中成「函数库」。
- **范围**：本期支持 Python（引擎 debugtalk 原生）；沙箱约束不做（内网可信团队）；
  函数执行失败归因 `case_issue`。
- **验收要点**：
  1. 新增函数 `gen_sign(appkey, ts)` 并在请求头里引用，执行时值正确；
  2. 语法错误的函数保存即被校验拦截（Python AST 检查）；
  3. 函数文件变更留痕（进 F8 变更历史）；
  4. 全局函数与项目函数同名时项目优先，优先级在 UI 明示。
- **工作量级**：M ｜ **依赖**：引擎 debugtalk 机制（已实测 A15/A16 系列验证）

### 第三梯队（P2：差异化亮点，视精力投入）

#### R7 压测模式（接入 hrp boomer） ｜ 待开发 ｜ P2 ⭐

- **目标**：用例/用例集一键转压测：并发数、持续时间、爬坡配置；报告含
  TPS / P50 / P95 / P99 / 错误率曲线。做完即拥有「轻量 JMeter」。
- **范围**：单机压测（boomer master 模式本期不接分布式）；压测执行与功能执行
  分开存储（run 带类型标记），不混入功能回归统计。
- **验收要点**：10 并发 30 秒压测回显服务，报告数字自洽（总请求数≈TPS×时长）；
  压测记录不出现在通过率趋势里。
- **工作量级**：L ｜ **依赖**：无（引擎能力已存在）

#### R8 敏感变量加密存储 ｜ 待开发 ｜ P2

- **目标**：环境变量/认证凭据/DB 连接串在**库内加密**（AES-256，密钥来自服务配置），
  掩码从「展示层打码」升级为「存储层加密」。
- **验收要点**：直接查库看不到明文；轮换密钥后旧数据可迁移；编译时自动解密。
- **工作量级**：M ｜ **依赖**：无

#### R9 企业登录（LDAP / OIDC） ｜ 待开发 ｜ P2

- **目标**：对接公司 LDAP/OIDC 登录，本地账号作为 fallback；组映射角色。
- **工作量级**：M ｜ **依赖**：无（内网部署时按需立项）

## 四、明确不做（及其理由）

| 项 | 理由 |
|:---|:---|
| 云端监控 / 多地域调度 | 自托管 + 内网直达是核心卖点，做云形态等于换赛道 |
| 任意 JS 前后置脚本（Postman 形态） | 结构化是差异化；逃生舱需求由 R6 函数库承接 |
| gRPC | 需 protobuf 运行时与动态描述符（服务端反射），投入产出比低，已单独立项结论 |
| API 市场 / 插件生态 | 生态需要用户基数，现阶段无意义 |
| 移动 / UI 自动化 | 引擎定位接口层，UI 测试另有成熟工具 |
| 仿抄 Postman 工作区/fork/merge 全套 | 只取「评审生效」这一最有团队价值的子集（R4），其余协作复杂度不值得 |

## 五、跟进机制

1. **立项**：从本文件选条目 → 走 spec-kit SDD（spec/plan/tasks）→ 开发；
2. **验收**：每个功能的「验收要点」逐条 HTTP/端到端验证（与 F1~F13 同标准）；
3. **回填**：完成后标题标 `✅ ｜ 已完成 ｜ 提交号`，同步《接口契约》《数据库设计》
   与 README；涉及引擎行为的补录《引擎实测记录》；
4. **调整**：优先级可随团队实际使用反馈调整，但「明确不做」清单的变更需要显式讨论。

**当前建议顺序**：R1 → R2 → R3（第一梯队），完成后回看第二梯队优先级。
