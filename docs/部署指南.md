# 部署指南

> 目标读者：要把平台部署到一台服务器上跑起来的人。
> 默认路径：**Linux + systemd + SQLite（单文件交付）**——这是与项目定位
> （30 人团队、单实例）一致的推荐形态；Windows 服务器见 §10，MySQL 见 §3 的说明。
>
> 部署总共只需要三样东西，先记住这张清单：
>
> | # | 东西 | 从哪来 |
> |:--|:--|:--|
> | ① | 平台单文件可执行文件（前端已内嵌） | 项目仓库 clone 后跑 `bash scripts/build.sh` |
> | ② | hrp 引擎二进制 v4.3.6 | HttpRunner 官方 release 下载（不是项目仓库里的东西） |
> | ③ | `config.yaml` | 从 `configs/config.example.yaml` 拷贝后改 4 个字段 |

---

## 1. 构建产物（在你的开发机 / 构建机上）

```bash
git clone https://github.com/Chunxia-zzz/httprunnerplatform.git
cd httprunnerplatform
bash scripts/build.sh                # 产出 ./httprunnerplatform.exe（Windows）
                                     # 或 ./httprunnerplatform（Linux，交叉编译见下）
```

- **必须用这个脚本，不能直接 `go build`**：前端 vite 产出在 `web/dist`，
  脚本负责拷进 `internal/webui/dist` 供 `go:embed` 内嵌，并在编译前校验内容存在
  （原因见 README「快速开始」）。
- 产物是**自包含**的：前端、静态资源全部内嵌，服务器上不需要 Node、不需要任何静态文件。
- 跨平台交叉编译：在 Windows 上给 Linux 服务器出产物 →
  `GOOS=linux GOARCH=amd64 bash scripts/build.sh /tmp/httprunnerplatform`。
- `SKIP_NPM=1 bash scripts/build.sh` 可复用已有 `web/dist`（只改了 Go 代码时省 1 分钟）。

> **离线内网部署**：构建机联网（拉 npm/Go 依赖），服务器完全离线——
> 把构建产物 + hrp 二进制 + config 三个文件拷过去即可，平台运行期**零外网依赖**
> （引擎遥测已在执行器内强制关闭）。

## 2. 服务器准备

推荐布局（与《项目方案》十一一致）：

```
/opt/httprunnerplatform/
├── httprunnerplatform        # ① 构建产物（chmod +x）
├── bin/hrp                   # ② 引擎（v4.3.6，linux_amd64）
├── configs/config.yaml       # ③ 配置（见 §3）
└── data/                     # 首次启动自动创建，不要手动建
    ├── platform.db           # SQLite 数据库（单文件）
    ├── workspaces/           # 用例工作区（按项目分目录）
    └── runtime/              # 执行工作区 + 报告归档
```

hrp 引擎：到 <https://github.com/httprunner/httprunner/releases/tag/v4.3.6>
下载 **linux_amd64** 包，解压出 `hrp` 放到 `bin/` 并 `chmod +x`。
（资产文件名以 release 页为准；锁死 v4.3.6——平台全部实测与归因逻辑以该版本为基线，
见《引擎实测记录》。）

⚠️ **`data/` 必须在服务器本地磁盘**。SQLite 绝不能放 NFS/Samba 等网络共享
（跨网络锁不住，会损坏数据库）。

## 3. 配置 config.yaml

```bash
cp configs/config.example.yaml configs/config.yaml
```

必改的 4 个字段（其余保持默认即可）：

| 字段 | 改成 | 说明 |
|:--|:--|:--|
| `auth.session_secret` | `openssl rand -base64 32` 的输出 | **必改**。默认值是占位符，知道默认值的人可伪造会话 |
| `engine.binary_path` | `/opt/httprunnerplatform/bin/hrp` | 指向 §2 放的引擎；留空则回退 `HRP_BINARY_PATH` 环境变量与系统 PATH |
| `database.driver` / `dsn` | 默认已是 `sqlite` + `data/platform.db` | 切 MySQL 时改这里，**切换前必须在预发环境完整回归**（CI 不测 MySQL，见《数据库设计》§0） |
| `server.port` | 按需（默认 8080） | 与防火墙 / 反代一致即可 |

启动后自动创建管理员 `admin / admin123`，**首次登录后立即改密**（右上角头像 → 修改密码）。

## 4. systemd 托管

`/etc/systemd/system/httprunnerplatform.service`：

```ini
[Unit]
Description=HttpRunner Platform
After=network.target

[Service]
Type=simple
User=hrp
WorkingDirectory=/opt/httprunnerplatform
ExecStart=/opt/httprunnerplatform/httprunnerplatform server -c /opt/httprunnerplatform/configs/config.yaml
Restart=on-failure
RestartSec=3
# 引擎遥测（GA4/Sentry）：执行器起 hrp 子进程时已自动注入 DISABLE_GA=true /
# DISABLE_SENTRY=true，这里无需配置；若要手工裸跑 hrp 排障，务必带上字面量
# true（写 1 无效，见《引擎实测记录》A20）。

[Install]
WantedBy=multi-user.target
```

```bash
useradd -r -s /sbin/nologin hrp && chown -R hrp:hrp /opt/httprunnerplatform
systemctl daemon-reload && systemctl enable --now httprunnerplatform
```

## 5. 首次启动验证（5 分钟）

```bash
# ① 进程活着
systemctl status httprunnerplatform

# ② 健康检查
curl -s http://127.0.0.1:8080/api/v1/healthz
# → {"code":0,"message":"ok","data":{"status":"ok",...}}

# ③ 引擎可用性（要登录态；浏览器登录后页面右上角也有展示）
#    或直接看接口：登录拿 cookie 后 GET /api/v1/engine/status
# → version 应显示 v4.3.6；不可用时 code=50001
```

浏览器走完一遍最小路径：登录 → **改默认密码** → 建项目 → 建用例 → 执行 →
看到步骤级结果与归因。全绿即部署完成。

对外暴露：最简单是防火墙直接放行 8080；需要 HTTPS/域名时前置一层 Nginx
反代到 8080 即可（平台是普通 HTTP 服务，无特殊头要求）。

## 6. 升级流程

```bash
systemctl stop httprunnerplatform
cp /opt/httprunnerplatform/httprunnerplatform /opt/httprunnerplatform/httprunnerplatform.bak  # 留回滚退路
cp /path/to/new-build/httprunnerplatform /opt/httprunnerplatform/
systemctl start httprunnerplatform && curl -s http://127.0.0.1:8080/api/v1/healthz
```

- **`data/`、`configs/`、`bin/` 全程不动**——数据库结构由启动时 AutoMigrate 自动
  增量迁移，不需要手工跑 SQL；升级失败时用 `.bak` 秒回滚。
- hrp 引擎**不要随手升**：归因与解析逻辑以 v4.3.6 实测为基线（风险 R1/R8），
  升级前先看《引擎实测记录》并完整回归。

## 7. 备份与恢复

SQLite 单文件 + 工作区目录，备份 = 拷贝三样：

```bash
# 建议 cron 每日一次（crontab -u hrp -e）
systemctl stop httprunnerplatform                       # 平台不在写入时拷才一致
tar czf /backup/hrp-$(date +%F).tar.gz \
    -C /opt/httprunnerplatform data/platform.db data/workspaces data/runtime/reports configs
systemctl start httprunnerplatform
```

- `data/runtime/runs/`（每次执行的临时工作区）**不需要备份**，只留 `reports/` 归档。
- 恢复 = 解包回原路径 + 重启。停机窗口 = 拷贝时间（几十 MB 级，秒级）。
- 想不停机热备：`sqlite3 data/platform.db ".backup '/backup/platform.db'"`，
  但仍要连同 `workspaces/` 一起拷（工作区里的 YAML 才是用例的真身，DB 只存结构化数据）。

## 8. 排障速查

| 症状 | 先看 | 常见原因 |
|:--|:--|:--|
| 页面 502 / 打不开 | `systemctl status`、`journalctl -u httprunnerplatform -n 50` | 进程没起；端口被占（`ss -ltnp \| grep 8080`） |
| 页面出现「前端未构建」提示页 | — | 产物不是 build.sh 出的（`go:embed` 里是占位目录），回 §1 重构建 |
| 建项目/执行报 `50001 引擎不可用` | `GET /api/v1/engine/status` | `engine.binary_path` 指错；hrp 没加执行位；架构不匹配 |
| 执行特别慢（每条多 1~5 秒） | hrp 子进程环境变量 | 遥测没关（须 `DISABLE_GA=true` 字面量；平台自动注入，检查是否绕过了执行器） |
| 登录后频繁被踢回登录页 | config | `session_secret` 与上次启动不同（每次重启都换了值？写死在 config 里） |
| 定时计划不触发 / 触发两次 | 部署拓扑 | **调度器单实例约束**：多实例部署会重复触发（见《项目方案》十一） |
| 接口返回 HTML 而不是 JSON | 请求路径 | 打错路径落进了 SPA fallback——接口一律 `/api/v1/...`，错了返回的是 JSON 404 |

## 9. CI 触发接入（可选）

流水线里用令牌触发执行（不走人肉登录）：

```bash
# 创建令牌：页面 → 项目 → CI 令牌（创建后只显示一次，库中只存哈希）
curl -X POST "http://server:8080/open/runs" \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"target_type":"plan","target_id":1}'
# 异步返回 run_id；流水线要同步等结果：加 ?wait=1
# 结果查询：GET /open/runs/{run_id}/result（同一令牌）——
# exit_code / attribution 可直接判定成败，契约见《接口契约》
```

## 10. 其他形态

- **Windows 服务器**：产物换 `windows-amd64` 版（build.sh 在 Windows 上默认就出 exe），
  托管用 NSSM 或任务计划程序替代 systemd，其余步骤相同。
- **Docker**：可以（单文件 exe 极适合容器化），但注意两点——`data/` 必须 mount 到
  本地卷；调度器单实例约束意味着**不能**简单起多副本。
- **MySQL**：改 `database.driver`/`dsn` 即可，但 CI 不测 MySQL——切换前务必在预发
  环境完整回归（时区 / JSON 列 / 排序行为差异），见《数据库设计》§0。
