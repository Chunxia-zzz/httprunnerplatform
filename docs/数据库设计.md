# 数据库设计 — M1

> 配套文档：[项目方案.md](项目方案.md)（第五章数据模型）、[接口契约.md](接口契约.md)、[引擎实测记录.md](引擎实测记录.md)
>
> **设计基线**：DB 是唯一真源，YAML 是可再生的编译产物（方案 4.2）。所有用例数据以结构化方式存在 DB 里，
> 按需编译成 hrp 工作区；**不做 DB ↔ YAML 双向同步**。

---

## 0. 通用约定

| 项 | 约定 |
|:---|:---|
| 主键 | `id` BIGINT UNSIGNED AUTO_INCREMENT（SQLite 下为 INTEGER PRIMARY KEY） |
| 时间 | `created_at` / `updated_at` DATETIME，由应用层统一写入 |
| 软删除 | 配置类表（project / environment / testcase / teststep / api_def / testsuite / test_plan）用 `deleted_at` 软删除<br>结果类表（run_record / case_result / step_result / assertion_result）**不用软删除**，按保留策略物理清理 |
| 字段命名 | 下划线小写（`base_url`），Go 侧用结构体 tag 映射 |
| JSON 字段 | **统一存 TEXT**，由应用层 `Marshaler/Unmarshaler` 负责序列化。理由：MySQL 的 `JSON` 与 SQLite 无对应类型，存 TEXT 可让同一套 GORM 模型在两种驱动下通用 |
| 布尔 | `TINYINT(1)`，Go 侧 `bool`。**DDL 一律不写 `DEFAULT`**，取值只由应用层显式赋值 —— 原因见下方「布尔列不带默认值」 |
| 枚举 | 存 VARCHAR(32)，**不用数据库 ENUM 类型**（跨驱动兼容 + 改枚举不需 DDL） |
| 字符集 | utf8mb4 / utf8mb4_0900_ai_ci（SQLite 无此概念） |
| 表前缀 | 无 |

### 布尔列不带默认值（重要）

TINYINT(1) 列在 DDL 与 GORM 模型里**都不写 `DEFAULT`**。这不是风格偏好，而是绕开一个会静默改数据的 GORM 行为：

> 字段只要带了 `default:` 标签，GORM 在 INSERT 时会把**该列整个排除**，交给数据库默认值兜底 —— 即使应用层传的是显式的 `false`。

后果是 `false` 被写成 `true`，且**没有任何报错**。已发生的两个真实案例：

| 字段 | 写入 | 实际落库 | 用户看到的现象 |
|:---|:---|:---|:---|
| `test_step.enabled` | `false` | `true` | 禁用步骤继续参与执行 |
| `case_result.clean_exit` | `false` | `true` | 被强杀的执行看起来"正常退出" |

这类错误的共同特征是**错得更"正常"**，因此极难发现。约定为：布尔列不带 DEFAULT，回归测试见 `internal/service/service_test.go` 的 `TestModel_布尔零值必须能落库`。

### 双驱动支持（重要）

方案原定 MySQL 8，但**本地开发环境通常没有 MySQL**。因此：

| 环境 | driver | DSN 示例 |
|:---|:---|:---|
| 生产 / 预发 | `mysql` | `user:pass@tcp(127.0.0.1:3306)/hrp_platform?charset=utf8mb4&parseTime=True&loc=Local` |
| 本地开发 / 单测 | `sqlite` | `data/platform.db` |

- SQLite 驱动选用 **纯 Go 实现**（`github.com/glebarez/sqlite`，基于 modernc.org/sqlite），**不引入 CGO**，与「单二进制交付」目标一致；
- 两种驱动共用同一套 GORM 模型与 AutoMigrate，因此**字段类型必须取交集**（见上方「JSON 存 TEXT」「不用 ENUM」）；
- 平台会用到的 `SELECT ... FOR UPDATE`、`JSON_EXTRACT` 等 MySQL 特有语法**一律不用**；并发靠「进程内任务队列 + 每次执行独立工作区」保证，不依赖数据库锁。

## 1. 表关系总览

```
user ──────────────────────────────┐
                                   │ owner_id / trigger_by
project ─┬─ environment            │
         ├─ api_def                │
         ├─ testcase ─┬─ teststep  │
         │            └─ param_dataset
         ├─ testsuite ─── suite_case
         ├─ test_plan              │
         └─ run_record ─── case_result ─── step_result ─── assertion_result
                                      └─ report_path / log_path
api_token
notify_config
```

`run_record → case_result` 是 M1 实测结论的直接体现：

> **一个用例 = 一个独立子进程**（方案 6.5）。一次运行会产生 N 个退出码、N 份 summary.json，
> 因此**归因与 `exit_code` 落在 `case_result`（用例级）**，`run_record` 只做汇总。

## 2. 枚举字典

| 枚举 | 取值 | 说明 |
|:---|:---|:---|
| `run_record.target_type` | `case` / `suite` / `plan` | 执行目标类型 |
| `run_record.trigger_type` | `manual` / `cron` / `ci` | 触发来源 |
| `run_record.status` | `queued` / `running` / `success` / `failed` / `error` / `canceled` | `failed` 有用例失败；`error` 平台/环境层面失败（含用例数对账不一致）；`canceled` 被终止 |
| **`case_result.attribution`** | `pass` / `system_under_test` / `environment` / `case_issue` / `ops` / `timeout` / `canceled` / `unknown` | **失败归因**，见第 4 节判别规则 |
| `step_result.status` | `pass` / `fail` / `error` / `skipped` | 步骤结果 |
| `teststep.step_type` | `request` / `api` / `testcase` / `transaction` / `rendezvous` / `think_time` / `websocket` | hrp 的 7 种步骤类型（M1 只开放 `request`，其余落库但 UI 后置） |
| `testcase.priority` | `P0` / `P1` / `P2` / `P3` | |
| `testcase.status` | `draft` / `active` / `disabled` | `disabled` 不参与执行 |
| `api_def.source` | `manual` / `har` / `postman` / `curl` | 接口定义来源 |
| `user.role` | `admin` / `member` | 仅两档，不做 RBAC |
| `environment.verify_ssl` | `bool` | 渲染为 `verify: true/false` |

## 3. 建表 DDL

> 以下 DDL 为 **MySQL 8** 语法，是权威定义。GORM 的 AutoMigrate 会按同一套模型生成等价结构；
> SQLite 下由 GORM 自动降级类型（VARCHAR→TEXT 等）。

### 3.1 user

```sql
CREATE TABLE `user` (
  `id`         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `username`   VARCHAR(64)  NOT NULL,
  `password`   VARCHAR(128) NOT NULL COMMENT 'bcrypt hash',
  `nickname`   VARCHAR(64)  NOT NULL DEFAULT '',
  `role`       VARCHAR(16)  NOT NULL DEFAULT 'member' COMMENT 'admin/member',
  `enabled`    TINYINT(1)   NOT NULL,
  `created_at` DATETIME     NOT NULL,
  `updated_at` DATETIME     NOT NULL,
  `deleted_at` DATETIME     NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_user_username` (`username`),
  KEY `idx_user_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户';
```

### 3.2 project

```sql
CREATE TABLE `project` (
  `id`             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `code`           VARCHAR(64)  NOT NULL COMMENT '唯一标识，同时作为工作区目录名',
  `name`           VARCHAR(128) NOT NULL,
  `description`    VARCHAR(512) NOT NULL DEFAULT '',
  `workspace_path` VARCHAR(512) NOT NULL DEFAULT '' COMMENT '留空则用 {workspace.root}/{code}',
  `hrp_version`    VARCHAR(32)  NOT NULL DEFAULT 'v4.3.6' COMMENT '引擎版本绑定，起警示作用',
  `owner_id`       BIGINT UNSIGNED NOT NULL DEFAULT 0,
  `created_at`     DATETIME     NOT NULL,
  `updated_at`     DATETIME     NOT NULL,
  `deleted_at`     DATETIME     NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_project_code` (`code`),
  KEY `idx_project_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='项目';
```

> `code` 限制为 `^[a-zA-Z0-9_-]{1,64}$`（会作为目录名与文件名片段，必须在应用层校验，防止路径穿越）。

### 3.3 environment

```sql
CREATE TABLE `environment` (
  `id`             BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `project_id`     BIGINT UNSIGNED NOT NULL,
  `name`           VARCHAR(64)  NOT NULL COMMENT '如 dev / test / staging',
  `base_url`       VARCHAR(512) NOT NULL DEFAULT '',
  `environs`       TEXT         NULL COMMENT 'JSON object：额外环境变量，渲染进 .env',
  `global_headers` TEXT         NULL COMMENT 'JSON object：全局请求头',
  `verify_ssl`     TINYINT(1)   NOT NULL,
  `is_default`     TINYINT(1)   NOT NULL,
  `created_at`     DATETIME     NOT NULL,
  `updated_at`     DATETIME     NOT NULL,
  `deleted_at`     DATETIME     NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_env_project_name` (`project_id`,`name`),
  KEY `idx_env_project` (`project_id`),
  KEY `idx_env_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='环境（渲染为 .env）';
```

**`.env` 渲染规则**（编译器实现，方案 3.3 v4.1+ 要求）：

```
base_url=http://127.0.0.1:8899
<environs 的每个 k=v，逐行>
```

- `verify_ssl` **不写进 `.env`**，写进用例 `config.verify`（hrp v4 的行为）；
- `global_headers` 不写进 `.env`，编译器合并进每条步骤的 `headers`（避免污染环境层语义）。

### 3.5 testcase

```sql
CREATE TABLE `testcase` (
  `id`              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  `project_id`      BIGINT UNSIGNED NOT NULL,
  `code`            VARCHAR(64)  NOT NULL COMMENT '文件名片段，须为标识符',
  `name`            VARCHAR(128) NOT NULL COMMENT '渲染为 config.name，同一项目内必须唯一（F11）',
  `module`          VARCHAR(64)  NOT NULL DEFAULT '' COMMENT '模块，用例树分组依据',
  `priority`        VARCHAR(4)   NOT NULL DEFAULT 'P1',
  `tags`            VARCHAR(255) NOT NULL DEFAULT '' COMMENT '逗号分隔',
  `status`          VARCHAR(16)  NOT NULL DEFAULT 'active',
  `description`     VARCHAR(512) NOT NULL DEFAULT '',
  `config`          TEXT         NULL COMMENT 'JSON：variables / parameters / headers / verify / export / weight',
  `request_timeout` INT          NOT NULL DEFAULT 0 COMMENT '单请求超时（秒），0=引擎默认',
  `case_timeout`    INT          NOT NULL DEFAULT 0 COMMENT '整用例超时（秒），0=用平台默认',
  `owner_id`        BIGINT UNSIGNED NOT NULL DEFAULT 0,
  `last_run_id`     BIGINT UNSIGNED NOT NULL DEFAULT 0,
  `last_status`     VARCHAR(16)  NOT NULL DEFAULT '',
  `created_at`      DATETIME     NOT NULL,
  `updated_at`      DATETIME     NOT NULL,
  `deleted_at`      DATETIME     NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_case_project_code` (`project_id`,`code`),
  UNIQUE KEY `uk_case_project_name` (`project_id`,`name`) COMMENT 'F11：summary.json 用 config.name 作唯一标识',
  KEY `idx_case_project_module` (`project_id`,`module`),
  KEY `idx_case_deleted_at` (`deleted_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用例';
```

> **`uk_case_project_name` 是硬约束，不是可选项。** 实测（F11）summary.json 以 `config.name` 为唯一标识，
> 重名将导致结果无法区分。**编译期还会再校验一次**，防止绕过 DB 约束的写入路径。

## 4. ⭐ `case_result.attribution` 判别规则

**实现位置**：`internal/parser`。**判别顺序不可调换**（实测结论，方案 6.3）：

| 优先级 | 判据 | attribution | 依据 |
|:---:|:---|:---|:---|
| 1 | 被用户取消 | `canceled` | 平台侧 |
| 2 | 超时强杀 | `timeout` | 平台侧 |
| 3 | `exit_code == 0` | `pass` | 实测 |
| 4 | **stderr 含 `panic:`** | **`system_under_test`** | **F8 —— 断言失败即 panic，优先级必须高于退出码** |
| 5 | `exit_code == 1` | `environment` | 实测：`do request failed`（连接被拒/DNS/超时） |
| 6 | `exit_code ∈ {9,18,31,32,33}` | `ops` | 执行机 Python/插件环境 |
| 7 | `exit_code ∈ [10,17] ∪ [20,24]` | `case_issue` | loader/parser 区间，用例或环境配置问题 |
| 8 | 其他非 0 | `unknown` | 保留原始日志人工判定 |

**辅助判据**：`clean_exit`（stdout 是否含 `hrp exit N`）。**非 0 退出码 + `clean_exit=0` ⇒ 一定是 panic**，
可与第 4 条交叉验证（panic 会跳过 `code.GetErrorCode()` 的打印）。

> **为什么第 4 条必须排在 `exit_code` 之前**：断言失败与部分环境错误**同为退出码 2**，
> 只看退出码一定会误判。这是 M1 实测最重要的修正。

## 5. 数据保留策略

| 表 | 策略 |
|:---|:---|
| `run_record` / `case_result` / `step_result` / `assertion_result` | 保留 `workspace.run_retention_days`（默认 90）天，超期由清理任务删除；**统计汇总长期保留**（后续里程碑） |
| `run_record` 级联 | 删除 run 时按 `run_id` 删除 `case_result → step_result → assertion_result`（应用层事务内级联，不依赖外键） |
| 归档文件 | `runtime/runs/{run_id}/` 整个目录随记录一起清理；`report.html` 如需长期留存，复制到 `runtime/reports/` |
| 配置类表 | 软删除，可恢复 |
