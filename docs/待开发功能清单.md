## 第一梯队（P1）

### F1 接口定义库 + 服务/模块层级 ✅ ｜ 已完成 ｜ P1 ⭐

**价值**：当前用例里的请求是「复制粘贴」的——同一接口在 20 条用例里写 20 遍，改 base 路径要改 20 处。
建立「项目 → 服务（模块）→ 接口」三层结构，用例通过**引用**接口定义来组装步骤，改一处全生效。
这也是用户明确提出的数据层级。

**现状依据**：
- `api_def` 表已建（`internal/model/model.go:382`：Code/Name/Method/Path/Headers/Params/Body/BodyType/Description/Source），**无任何 CRUD 端点**
- `test_step.ref_api_id` 字段已建，`step_type=api` 在 `internal/compiler/compiler.go:348` 被显式拒绝（「M1 尚未开放」）
- `test_case.module` 是既有分组惯例（字符串），`GET /projects/:id/cases/tree` 已按它分组

**技术要点**：
- 服务/模块采用 `api_def.module` 字符串（与用例既有 `module` 一致），服务清单由 `GROUP BY module` 得出，不新建表
- 新增 `/projects/:id/apis` CRUD + `/projects/:id/apis/tree`（按 module 分组）
- 编译器放开 `step_type=api`：按 `ref_api_id` 展开为请求步骤（**内联展开**，导出的 YAML 保持自包含，不依赖 api/ 目录）
- 前端：接口库页（服务分组树 + 接口列表）、用例编辑器步骤类型切换「请求 / 引用接口」

**依赖**：无（编译器、模型、前端骨架均已具备）

**实现记录**（2026-11-16，`specs/002-api-library`）：
- `api_def` 增加 `module`；新增 5 个端点（`/projects/{id}/apis`、`/projects/{id}/apis/tree`、`/apis/{id}` CRUD）
- 编译器 `Input.APIs` + `step_type=api` **内联展开**为 request（`ref_api_id` 不泄漏进 YAML）
- 保存期 + 编译期双重校验「存在且同项目」；被引用删除返回 40003（`used_by` 派生计数）
- 前端：接口库页（服务分组 + 编辑表单）、用例编辑器「直接请求 / 引用接口」切换
- 验证：单测（CRUD/重名/删除保护/跨项目/内联/校验分支）+ 真实 hrp 端到端 7 步
  （建接口 → 引用执行成功 → 改接口未改用例即生效 → 删除保护）

**验收要点**：
1. 能建服务（module）+ 接口定义，列表按服务分组
2. 用例步骤可改为「引用接口」并选择接口；编译后 YAML 是内联 request（可离线执行）
3. 修改接口定义 → 所有引用它的用例下次执行自动生效（无需改用例）
4. 引用不存在的接口 / 跨项目引用 → 编译期报错且错误可读

### F2 通知（企微 / 钉钉 / Webhook） ｜ 待开发 ｜ P1 ⭐

**价值**：定时巡检没有告警等于没有巡检。计划失败自动推送到群，是 30 人团队最容易感知的功能。

**现状依据**：`notify_config` 表已建（`internal/model/model.go:703` 有 TableName），`notify` 包为空壳；
`test_plan.notify_config_id` 字段已建；`configs/config.example.yaml` 曾有一段代码不读取的 `notify` 死配置（2026-11-03 已删）。

**技术要点**：通知配置 CRUD + 计划绑定 + 发送器（企微/钉钉机器人 webhook 格式不同，需各一个适配）；
触发点：计划执行结束（成功/失败/连续失败 N 次）；失败重试与超时；密钥脱敏展示。

**依赖**：F1 无关，可并行

**验收要点**：配置后手动触发「发送测试消息」成功；计划失败后群里收到含 run 链接的消息；敏感 webhook 地址非管理员不可见。

**依赖**：建议在 F1 之后（保存出口直接写接口库）

### F4 Mock Server（按接口定义自动生成） ✅ ｜ 已完成 ｜ P2

**价值**：上下游没联调好时先跑通链路；把 F1 的接口定义直接变成 mock 端点。

**现状依据**：平台自带 mock 服务经验（`testdata/body-probe`、e2e 脚本里的 8899 桩服务）；`api_def` 有 Path/Body 足以生成默认响应。

**技术要点**：Mock 规则表（path+method → 状态码/体/延迟/条件匹配）；开关按项目；
与真实服务端口隔离（如 `/mock/{project_code}/...`）；记录命中日志便于排查。

**依赖**：F1（接口定义）

**实现记录**（2026-11-17，`specs/004-mock-server`）：
- 项目级开关 `project.mock_enabled`；公开端点 `ANY /mock/{projectCode}/*path`
  （免鉴权、独立前缀、直接回放响应）
- 匹配：路径归一化（去协议/host/`$base_url`/query）+ 段级精确匹配，
  `{x}`/`:x`/`$x` 为单段通配；方法不一致返回 405，未命中 404 列出已配置路径
- 命中日志：内存 ring（每项目 200 条，重启即失），前端可刷新查看
- 前端「Mock 服务」页：开关、基址与 curl 示例（可复制）、接口清单、命中日志
- 验证：表驱动单测（归一化/匹配/生命周期/日志上限）+ curl 端到端 6 步

**验收要点**：开启 mock 后请求命中返回配置的响应；未命中的路径返回明确 404 说明；命中记录可查。

**价值**：企业里接口文档基本都是 OpenAPI，比 Postman 集合导入更贴合公司场景；导入即生成服务分组 + 接口定义。

**现状依据**：导入框架已具备（`importsvc.go` 支持 Postman/HAR/curl，含 preview/commit 两段式）；har→平台的字段映射模式可复用。

**技术要点**：解析 OpenAPI 3.x / Swagger 2.0（servers→base_url、paths→api_def、components.schemas→示例体）；
`module` 取自 tags[0] 或路径首段；与 F1 的服务分组对齐。

**依赖**：F1

**实现记录**（2026-11-18，`specs/005-openapi-import`）：
- 解析器支持 OpenAPI 3.x / Swagger 2.0（JSON+YAML），映射 tag→服务、路径模板保留 `{id}`、
  `$ref` 深度 5 + 防环、按 schema 生成示例值
- ⭐ `api_def` 新增 `response_body`/`response_type`：请求体（编译内联）与响应示例（Mock）
  分离，Mock 优先用响应示例、为空回退请求体
- 预览/提交两段式；冲突标记 + skip/overwrite 策略；逐条失败报告
- 前端接口库页「导入 OpenAPI」：拖拽上传、预览勾选、冲突标记、策略选择、结果提示
- 验证：解析单测 5 组（两代规范/循环 ref/版本拒绝/去重/提交策略）+ 端到端 6 步

**验收要点**：导入一个真实 OpenAPI 文件后接口按 tag 分组；preview 能列出将创建的接口数；重复导入有冲突策略（跳过/覆盖）。

### F7 认证助手 + 动态变量 ｜ 待开发 ｜ P2

**价值**：现在认证只能手写 header；登录接口拿到的 token 要人工复制到环境变量。表单化 + 自动传递能省掉大量出错。

**现状依据**：环境变量与用例变量已支持；提取（extract）已支持；hrp 支持 variables 层级。

**技术要点**：认证类型（None/Bearer/Basic/API Key/继承环境）；动态变量 `{{$timestamp}}`/`{{$uuid}}`
（引擎不支持则平台编译期替换）；token 传递：登录接口 extract → 环境/会话变量的约定。

**依赖**：无（可与 F1 并行）

**验收要点**：选择 Bearer 后可只填 token 值；登录接口提取的 token 被后续请求自动引用；动态变量每次执行取值不同。

### F10 多协议（WebSocket / gRPC / GraphQL） ｜ 待开发 ｜ P3

**价值**：覆盖非 HTTP 接口；但引擎侧支持有限（hrp 有 websocket 步骤类型，gRPC/GraphQL 无原生支持）。

**技术要点**：WS 步骤可依托 hrp 的 `websocket` 类型（需实测）；gRPC/GraphQL 需平台自研执行器或通过 HTTP 包装；
**先做技术验证再定范围**。

**依赖**：引擎能力验证（实测记录新增条目）

**验收要点**：按协议分别给出「已支持/不支持」的明确结论，不做半成品。

### F11 性能回归告警 ｜ 待开发 ｜ P3 ⭐差异化

**价值**：平台已有「最慢接口」与「基线对比」，往前一步就是「本次比基线慢 30% → 告警」。Postman 的监控很弱，这是差异化。

**现状依据**：`stats/slowest`、`GET /projects/:id/baseline` 已具备；`step_result.elapsed_ms` 已落库。

**技术要点**：基线取最近 N 次中位数；阈值（绝对 ms / 相对 %）；命中后走 F2 通知；趋势图上标注回归点。

**依赖**：F2（通知出口）

**验收要点**：构造慢请求后统计页标红并告警；误报率可控（同接口波动 < 阈值不报）。
